# Contributing

Thanks for helping with `llmentary` (the Python client and pytest plugin).

By participating you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md).
Security reports go through [SECURITY.md](SECURITY.md), never a public issue.

## Requirements

- Python 3.9 or newer
- Go 1.26 if you build the proxy locally; otherwise set `LLMENTARY_BIN` to a
  prebuilt `llmentary` binary
- An OpenAI API key only if you run the live e2e suite

## Development install

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev,openai]"
```

## Checks

```bash
ruff check .
mypy
pytest -m "not e2e"
```

Unit tests and fake-upstream integration tests share that pytest selection.
Integration tests that talk to the real Go proxy are skipped unless
`LLMENTARY_BIN` or `LLMENTARY_PROXY_URL` is set.

### Local proxy

Build the proxy from `barzoj-co/llmentary` (Go 1.26):

```bash
go build -o /tmp/llmentary ./cmd/llmentary
export LLMENTARY_BIN=/tmp/llmentary
pytest -m "not e2e"
```

Or attach to an already running proxy with `LLMENTARY_PROXY_URL` and
`LLMENTARY_CONTROL_URL`. See [docs/pytest.md](docs/pytest.md).

### Live OpenAI e2e

These tests must actually run. They fail the session if any e2e test is
skipped.

```bash
export LLMENTARY_E2E=1
export OPENAI_API_KEY=...
export LLMENTARY_UPSTREAM_BASE_URL=https://api.openai.com/v1
export LLMENTARY_UPSTREAM_API_KEY="$OPENAI_API_KEY"
export LLMENTARY_BIN=/tmp/llmentary
pytest -m e2e -vv
```

Never print, log, or commit the API key or any `Authorization` / `api-key`
value.

Same-repo CI runs those tests in the `openai-e2e` job, which uses the
`openai-e2e` GitHub Environment. Maintainers approve that deployment on each
PR (and on push to `main`) before `OPENAI_API_KEY` is available to the job.
Python unit and fake-upstream integration jobs do not use the environment and
do not wait. `e2e-gate` fails unless live e2e succeeded.

## Pull requests

- Use a [Conventional Commit](https://www.conventionalcommits.org/) title
  (`feat:`, `fix:`, `docs:`, `ci:`, `chore:`, …). release-please uses these
  titles to bump the Python package version. CHANGELOG.md is generated by
  release-please on the first release.
- Run ruff, mypy, and `pytest -m "not e2e"` before you push.
- Document only behavior that exists in the tree.
- Note breaking changes in the PR.

## Dependencies and coverage

Renovate opens grouped dependency PRs (see `renovate.json`). Patch and digest
updates automerge. The bundled proxy pin in `PROXY_VERSION` does **not**
automerge.

Coverage is collected on the Python 3.13 CI leg and uploaded to Codecov from a
dedicated tokenless job (no OIDC). The Codecov project and patch statuses are
informational and do not fail PRs.

## CI configuration required

- `secrets.LLMTESTLAB_REPO_TOKEN`: read-only Contents token for private
  repository `barzoj-co/llmentary`. Used only to check out and build the real
  Go proxy in CI, and to fetch GoReleaser assets when building release wheels.
  TODO: remove once llmentary is public. Keep this secret name; it is an
  existing org secret.
- `secrets.OPENAI_API_KEY`: used by OpenAI E2E tests on push and non-fork PRs.
  Those tests actually run (they do not skip) when this secret is present.
- PyPI Trusted Publishing: configure PyPI project `llmentary` to trust this
  repository's `release.yml` workflow and `pypi` environment for tag `v*`
  releases. No PyPI API token is used. Publish stays gated on
  `vars.PYPI_PUBLISH_ENABLED`. See [docs/releasing.md](docs/releasing.md).

CI builds the real Go proxy from source (`go build ./cmd/llmentary`) and points
tests at it with `LLMENTARY_BIN`. Integration tests talk to a fake OpenAI
upstream through that real binary. E2E tests talk to the real OpenAI API
through the same real binary.

Proxy binary lookup, wheel platforms, and `LLMENTARY_START_COMMAND` are
documented in [docs/binaries.md](docs/binaries.md).
